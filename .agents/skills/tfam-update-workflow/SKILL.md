# TFAM updates on cloud

Read AGENTS.md and docs/AI-OPERATING-WORKFLOW.md before a TFAM update. Read only the relevant skill/reference for the current task.

Establish current main, issue, actual production/source provenance and overlapping work. Turn the owner's request into observable acceptance criteria while preserving canon and live data. Reuse a suitable active task branch or create one; preserve concurrent edits.

Use the workflow's routing table for web research, design, React/performance, motion, tests and media. Skill selection and ordinary reversible preparation do not require a repeated owner review. A skill is not execution access, account entitlement or permission to deploy.

Implement with the incumbent stack on cloud. Match validation to the changed behavior; UI/logic work needs relevant build/type/domain checks and rendered desktop/mobile evidence. Documentation/skill-only work needs integrity, naming, links, scope and conflict review, without claiming runtime tests.

Keep PRs concrete and reviewable. Report changed files, evidence and limitations. Merge or publish only within the owner's authorization for that task; this skill does not grant blanket future merge/deployment permission. Do not ask the owner to approve an undeveloped plan when independent authorized work remains.

After authorized release, record exact GitHub/Sites mapping, version, deployment ID, URL, tests and rollback target. If a stage is unavailable, complete independent work and describe the exact remaining requirement; do not label saved/committed work as live.
